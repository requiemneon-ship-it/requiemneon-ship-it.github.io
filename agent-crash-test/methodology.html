Methodology

How the current prototype is evaluated and what its numbers do — and do not — prove.

Controlled benchmark

The current benchmark contains 36 deterministic synthetic cases: 25 seeded defect cases and 11 clean controls.

For each case we define the expected finding set before execution. A case passes only when the observed finding set equals the expected set.

recall    = true positives / (true positives + false negatives)
precision = true positives / (true positives + false positives)

Current controlled result: recall 100%, precision 100%, FP 0, FN 0.

This is not an estimate of production accuracy. The benchmark is small, synthetic and built around the failure classes implemented by the prototype.

Failure workflow

FIND
  ↓
SHRINK
  ↓
REPLAY
  ↓
EXPORT REGRESSION + POLICY
  ↓
FIX
  ↓
VERIFY FIX

A finding is more useful when it is reproducible. The shrinker removes turns while the same finding still appears. The minimized case is replayed several times. The exported regression artifact includes the detection policy when the finding depends on one.

Current deterministic finding classes

Repetition loops, duplicate tool calls, identity drift, target exceptions, stable-state violations, monotonic-state regressions, missing required state, forbidden tools, missing required tools, tool-order violations, tool bursts, and repeated non-idempotent side effects.

External pilots

External testing requires target-owner authorization and should use staging/demo access. Before sending requests, the preflight validates URL/configuration, environment-backed secrets and the request budget. The runner supports pacing and a hard maximum request count.

No public third-party agent is automatically probed merely because it has a public demo.
